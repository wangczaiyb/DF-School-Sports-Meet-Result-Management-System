# 校园运动会赛事成绩管理系统

一套可在 Windows 本地运行、也可部署到学校服务器的运动会赛事管理系统。系统实现开发人员、体育部老师、裁判员、计分员、裁判兼计分员和学生六类使用场景，正式数据由 Python 后端写入项目内 SQLite 数据库，不使用 Docker、MySQL 或浏览器本地存储作为数据源。

## 已实现功能

- 三身份入口登录，账号角色匹配校验，连续失败 5 次锁定 15 分钟，密码 bcrypt 哈希保存。
- 开发人员账号、配额、编辑、冻结/解冻、重置密码、强制下线和系统品牌配置。
- 多届运动会、结构化比赛项目、项目级赛程/登记/审核/导出权限；同一年可以建立多届、不同名称或类型的运动会，各届赛事及项目相互隔离。运动会、项目、基础名单、学院代表队、计分模型、权限、赛程及成绩草稿均提供增删改查。
- 每个项目独立维护初赛、晋级赛、决赛名单；个人项目按学号关联学生，接力/团体项目按学院代表队关联。
- 参赛检录、候补、缺席、退赛状态，自动分组排道，按已发布名次生成下一轮正式/候补名单，并可导出 Excel 分组表。
- 可版本化计分模型，前八名默认 `9、7、6、5、4、3、2、1`，接力/集体倍率和并列名次平均积分。
- 内置跳绳赛制工作台，可按届次一键建立“前单跳”“集体单摇跳”“8 字绕绳跳”三个项目，校验学院 22 人代表队、各项目上场阵容及男女比例，并按项目规则结构化录入成绩。
- 成绩草稿、提交审核、裁判审核、退回、体育部终审和最终发布；已发布修改保留发布快照。
- 公开成绩中心、最新发布、前三名、学院团体积分、已发布赛程和 30 秒轮询。
- 学生账号激活、本人赛程、已发布成绩和晋级状态；学生账号不强制修改初始密码，也不影响账号未激活时的报名和成绩登记。
- 学生名单 Excel 导入与模板下载、学生手动录入、按届次录入学院集体/代表队、正式成绩单 Excel 导出、审计日志。
- Python + SQLite 正式数据存储，数据库、成绩单和备份均保存在本项目 `data` 目录。

## 一键启动

Windows 用户可直接双击项目根目录的 **`一键启动.bat`**。脚本会使用本机 Python 启动后端、使用 Node.js 启动前端，安装缺少的项目依赖，等待服务就绪后自动打开浏览器。全程不需要 Docker，也不需要另行安装数据库。需要停止时双击 **`一键停止.bat`**。

### 运行环境

- Python 3.12 或更高版本
- Node.js 22 或更高版本
- 不需要 Docker、MySQL、SQL Server 等数据库软件

也可以在项目根目录手动运行一键脚本：

```powershell
.\start-local.ps1
```

启动后的访问地址：

- 系统前端：<http://localhost:5173>
- API 文档：<http://localhost:8000/docs>
- 健康检查：<http://localhost:8000/health>

正式数据库文件保存在 `data/sports_meet.db`，Excel 导出保存在 `data/exports`，数据库备份保存在 `data/backups`。复制整个项目文件夹即可连同数据一起迁移。

停止服务：

```powershell
.\stop-local.ps1
```

## 推荐业务流程

1. 在“赛事与项目”建立运动会及个人、接力或团体项目。
2. 在“名单录入 → 学生资料库/学院代表队”导入或维护基础资料。
3. 在“项目参赛名单”选择项目和初赛/晋级赛/决赛，加入实际参赛学生或学院；可进行检录、自动排道和分组表导出。
4. 在“赛程管理”按项目和轮次发布比赛、检录时间及场地。
5. 在“成绩工作台”按该项目该轮名单登记成绩，依次提交、审核、终审发布。
6. 初赛或晋级赛成绩发布后，可在名单页“按名次生成下一轮”，学生端会按学号自动同步晋级信息。

## 跳绳赛制

开发人员或体育部老师可以从左侧菜单进入“跳绳赛制”。系统以运动会届次为数据边界，因此同一年可以分别建立春季运动会、田径运动会、趣味运动会等多届赛事；不同届次允许使用相同的跳绳项目编号，不会相互冲突。

### 初始化与代表队

1. 先在“赛事与项目”建立或选择目标运动会。
2. 在“名单录入 → 学院代表队”中为该届运动会维护学院队伍，每队必须登记 `22` 名队员。
3. 进入“跳绳赛制”，选择目标运动会，点击“初始化/同步跳绳赛制”。该操作是幂等的：重复执行只会同步项目、决赛轮次、学院报名和计分模型，不会重复创建项目。
4. 依次选择三个跳绳项目，为各学院配置上场阵容。只有队伍总人数、角色人数和男女比例全部符合规则后，才能录入成绩。

### 项目与阵容规则

| 项目 | 队伍总人数 | 上场阵容 | 比赛时间 | 排名依据 |
|---|---:|---|---:|---|
| 前单跳计时计数团体挑战赛 | 22 人 | 男跳绳者 5 人、女跳绳者 5 人 | 每人 1 分钟 | 10 名队员有效次数之和，次数多者列前 |
| 集体单摇跳 | 22 人 | 摇绳者 2 人（性别不限）、男跳绳者 5 人、女跳绳者 5 人 | 最长 5 分钟 | 完成 30 次时用时少者列前；未完成时按有效次数由多到少排列，且排在完成队伍之后 |
| “8”字绕绳跳 | 22 人 | 摇绳者 2 人（性别不限）、男跳绳者 10 人、女跳绳者 10 人 | 5 分钟 | 全队有效完成次数，次数多者列前 |

阵容中的同一名学生不能同时担任摇绳者和跳绳者。系统会校验学生是否属于所选学院代表队，并检查上场人数、角色和跳绳者性别比例。

### 成绩录入与计分

- 前单跳分别录入 5 名男生和 5 名女生的个人次数，系统自动汇总团体总次数。
- 集体单摇跳完成 30 次时录入实际用时；未在 5 分钟内完成时选择“未完成”，录入已完成的有效次数（`0–29` 次）。
- “8”字绕绳跳录入 5 分钟内的有效完成次数。
- 三个项目默认使用前八名 `9、7、6、5、4、3、2、1` 分的跳绳专用计分模型。
- 成绩或用时相同时名次并列，并平均所占名次的单项积分。例如两队并列第一时，各得 `(9 + 7) / 2 = 8` 分，下一名从第三名开始。
- 成绩仍需依次经过“保存草稿 → 提交 → 裁判审核 → 体育部终审 → 发布”。发布时会保存跳绳成绩明细快照，后续修改草稿不会直接改变公开成绩。
- 公开成绩中心会按项目显示“总次数”“完成 30 次及用时”或“未完成及有效次数”，不会展示系统内部排序值。

## 学生名单导入与成绩单导出

- 学生名单模板：[学生参赛名单导入模板.xlsx](outputs/sports-meet/学生参赛名单导入模板.xlsx)
- 体育部老师或开发人员进入“名单录入 → 学生资料库”，下载模板并导入学生名单。

## 数据库与迁移

数据模型覆盖系统要求的 24 类核心业务与配置表，并为用户名、学号、项目、权限、成绩状态、赛程发布时间建立唯一约束或索引。

```powershell
python -m alembic -c backend\alembic.ini upgrade head
```

- Alembic 当前迁移版本为 `20260901_0009`（HEAD），支持动态配置数据库 URL，并在迁移脚本中包含针对 SQLite 批处理临时表的防护及列幂等性校验。
- 迁移机制通过 `scripts/verify_alembic_3scenarios.py` 自动化验证三种发布场景（全新空白库初始化、从历史 0001 增量升级、表结构超前但迁移版本滞后补齐），全部通过并保持外键与完整性完好。
- Python 后端启动时会自动校验并升级数据表，并执行幂等演示数据初始化。正式使用前请在 `.env` 中设置 `AUTO_SEED=false`，并单独维护学校正式基础数据。
- SQLite 连接通过 SQLAlchemy 事件钩子统一强制开启外键支持（`PRAGMA foreign_keys = ON`）、启用预写日志模式（`PRAGMA journal_mode = WAL`）并设置 30 秒忙等待（`PRAGMA busy_timeout = 30000`），保证高并发读写下数据的强一致性。

SQLite 数据库的备份与恢复：

```powershell
.\scripts\backup-local.ps1 -Label before-import
.\scripts\restore-local.ps1 -BackupFile .\data\backups\sports_meet_时间_before-import.db
```

恢复会覆盖当前数据库，脚本会校验备份必须位于 `data/backups`、验证完整性并要求输入二次确认。建议在正式比赛前、名单导入前和成绩发布后各执行一次备份。

## 生产部署提示

- 修改 `.env` 中所有默认密码、`SECRET_KEY`、CORS 来源和域名；保持数据库地址指向受保护的 `data/sports_meet.db`。
- 使用 HTTPS，并限制 `/docs`、数据库和备份文件的公网访问。
- 将 `data/sports_meet.db`、`data/exports`、`data/backups` 纳入学校服务器备份策略。
- Nginx 示例位于 `deploy/nginx.conf.example`；学校名称、系统名称、主色和页面文案在开发人员后台配置。
- 不要把 `.env`、数据库文件、导出成绩单或备份文件提交到公开代码仓库。

## 数据存储说明

SQLite 是 Python 原生支持的文件数据库，不是临时验证方案。系统中的账号、赛事、权限、赛程、成绩、审核、发布与审计数据都由 Python 后端统一写入 `data/sports_meet.db`。请勿使用文本编辑器直接修改该文件，也不要在系统运行时用文件同步软件覆盖它。
